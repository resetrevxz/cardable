# Electron Milestone 2

Implementation stabilized on 5 October 2026; public-service acceptance remains pending.

The first agent supplied an updater service boundary and an inactive Settings component. This pass connected the existing surface, fixed its duplicate download/install handlers, replaced simulated RPC with an optional IPC client, and completed the updater's guarded lifecycle. The existing Electron main/preload/renderer split remains in place.

## Implemented

- Settings → About contains current/latest version, update status, download percentage/bytes, plain-text release notes, retry, explicit Install and restart, and Later. Reopening Settings restores the postponed install action.
- Checks start after 30 seconds in configured packaged builds and recur every six hours. Downloads and restarts require the user's action. Development/unconfigured builds do not contact a provider.
- Main-process install IPC requests a renderer save/settings flush and native backup acknowledgment. Failure or timeout blocks installation. Ordinary closing still has a bounded fallback for an unresponsive renderer.
- GitHub provider configuration is generated by electron-builder; there is no runtime setFeedURL. Public owner/repository/Discord identifiers can come from desktop-release.json or CI variables. No placeholder release repository is contacted.
- Tag-triggered Windows CI installs the lockfile, validates versions/notes, tests, builds NSIS, tests the ASAR application, verifies updater hashes, and uploads a draft GitHub Release. Dedicated public release repositories are supported.
- Discord uses local IPC in the main process, an optional public Application ID, reconnect and failure handling, throttled broad screen activity, elapsed session time and optional branding asset. Off is the default; disabling clears activity and closes the connection. The preference is written under userData. No credentials are required to run/build Cardable.
- Settings has save/log folder shortcuts and diagnostic copying. Production logs rotate during long sessions and capture startup, updater states, RPC connection state, renderer failure and main exceptions.

## Tested

Five injected service tests cover updater progress/install guards, offline retry, concurrent operations, unconfigured behavior, Discord absence, connection/reconnection, activity privacy and disabling. The real Electron smoke test exercises the settings UI's progress and action routing, diagnostics, invalid URL/save/RPC rejection, install-before-download rejection, core game interaction and repeated save recovery. These tests do not substitute for a real remote update or a live Discord session.

NSIS and blockmap generation succeeded locally. Installed/uninstall and local two-version update tests are tracked in the Milestone 3 report.

## External acceptance

There is no Git remote configured in this checkout and no owner-provided public release repository or Discord Application ID. Consequently CI execution, GitHub release detection/download/install and a real Discord-connected session cannot be claimed. The source workflow and local tests are ready for those services. A public two-version GitHub test remains mandatory before calling the updater release-accepted. See RELEASING.md and UPDATES.md.
