# Daily Shop — Stage 2 acceptance

Date: 2026-10-12. Worktree: `D:/CardableV2/Shop`; branch: `feature/daily-shop`.

## Implemented

- The Stage 1 fixture array was replaced by four saved daily offers from the complete presently eligible catalog. Current catalog inspection found **126** eligible GPU definitions. Retired placeholders, non-pullable/locked/unreleased cards and rarity tiers with absent/nonpositive odds are excluded. Secret is eligible because it is currently pullable with positive odds and genuine card definitions; Limited is not because its tier is non-pullable with no active chance. A card's placeholder artwork status does not exclude its published/pullable definition. Owned duplicates remain eligible on future days.
- Selection groups by canonical rarity, weights nonempty pools by the rarity table's relative `chance`, selects a tier, then selects one remaining card uniformly. It removes the selected card and repeats. The source chances total 100.5, so the engine normalizes the available positive weights each draw. Empty and malformed tiers consume no probability. Fewer than four eligible cards produce an explicit underfilled state without partial offers or a loop. `C.shopState.odds(...)` provides transparent dev diagnostics without claiming a guaranteed four-slot distribution.
- A per-player random seed is saved once. `YYYY-MM-DD` is built from local calendar fields, including DST and timezone behavior. Daily generation uses a seeded PRNG and commits one snapshot of IDs, variants, quotes and four `purchased:false` flags before displaying it. The 32-day bounded cache restores previous dates on clock reversal. UI checks the current local day on its single 30-second timer and on visibility/save events. Returning to an expired detail shows a clear unavailable notice; replacing a save refreshes the open Shop.
- Variants use the existing `C.variants.roll` 10% coating policy and weighted registry. The saved `variantId` is used in tile and full card preview, with `cardSkinId:null`; no preview serial, instance or entitlement is allocated. The permanent Titan feature uses its registered pack ID and a fixed local Shop quote.
- Shop quotes come from `C.data.shop`, not `marketValueUsd`. Baselines are multiplied by the 1.25 convenience factor, optional per-card collectibility factor and 1.20 variant factor, then rounded upward to 50 Credits. Example quotes: Basic standard **1,150**, Rare standard **3,000**, Rare coated **3,600**, Mythical standard **9,750**; permanent Titan Pack **7,600**. These are provisional local Credits values, not market prices or discounts.
- The hold control remains a non-spending practice interaction. Stage 2 changes `save.shop` only. It does not debit Credits, consume pack stock, mark a slot purchased, create a card instance or grant a pack.

## Verification

- `tools/check-shop-stage2.cjs` ran against local `file://` in Chrome: four unique real offers, same-day/reload stability, deterministic variants, another day's roll, clock forward/backward cache, spring/fall DST keys in `America/New_York`, strict invalid-price rejection, historical removed ID retention, underfilled and depleted catalog fixtures, save export/import round-trip, storage-failure rollback, expired inspection, four rendered tiles, color and monochrome Very Low at 1366×768 and 390×844, reduced motion, no normal-run console errors, and unchanged Credits/inventory/ordinary stock/purchased flags. Intentional storage-failure logging was excluded from the normal-run console assertion.
- Statistical fixture: 12,000 first-slot draws with rarity weights 7:2:1 yielded Basic **8,321 (69.34%)**, Common **2,443 (20.36%)**, Rare **1,236 (10.30%)**, within 2 percentage points of expected 70/20/10. An empty tier with weight 1,000 stole no probability. The test also checks uniqueness after pool depletion.
- Pricing guardrail fixtures use hypothetical resale ceilings per rarity and a hypothetical Titan expected-value ceiling of 6,200 Credits. All standard Shop quotes exceed those resale ceilings and the featured 7,600 quote exceeds the synthetic pack ceiling. The current game has no quick-sell payout, so these are test assumptions, **not** observed sale values or a real Titan pack expected return.

## Remaining acceptance

A live clock/timezone change during an in-progress hold has no transaction in this stage; Stage 3 must enforce the committed day/offer check at debit time. The 32-day cache does not freeze quotes indefinitely if a much older day is revisited after a catalog or policy update. Packaged Electron and hardware frame profiling remain separate from the `file://` browser check.
