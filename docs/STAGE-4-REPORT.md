# Stage 4 — Pack and menu

## Done

- Replaced all Stage 1 placeholders with a data-driven pack, live countdown and stock vials, currency counter, and visual inventory affordance. Local classic scripts still boot from `index.html` with no server/build/CDN dependency.
- The enabled timer pack's name, material and wrapper come from pack data. Ready uses an opaque monochrome foil wrapper, crimped seams, subtle brushing, cursor-following shine, five-pixel/six-second float, and gentle lean. Two stored packs show a smaller, dimmer, slightly blurred rear wrapper floating out of phase.
- Waiting uses the shared glass recipe and a timestamp-derived fluid fill. Each rendered frame reads `timers.progress(Date.now())`, rather than using the one-second tick as the visual fill clock. A soft meniscus and small drifting specks give the fluid a restrained surface treatment.
- Real `pack:ready` events complete the fluid, crossfade to the opaque wrapper, sweep one bright line over the front, and add a short lift. The moment is deduplicated against actual stock gains. Load-time catch-up is observed after UI subscribers mount; repeat ticks, repeated events, reloads of already-ready packs, and simulated title events do not replay it. A batch catch-up is one ready moment, even if it fills both slots.
- Added a reusable rolling-number component. Stable digits retain their DOM slots; changed digits roll, including a carry such as 9 to 10. Countdown uses `7h 12m`, `42m 10s`, and `38s`; the cap reads `Stock full`. The exact timer brightens on pack hover/focus. Two glass vials ease to their saved stock level and slosh briefly during fills/drains.
- Currency reads the saved balance, counts toward changed values and shimmers briefly. `Cardable.currency.add(n)` validates a non-negative safe-integer addition, persists it, and emits `currency:changed`. There are no gameplay earning or spending actions.
- Added a slowly breathing/nudging chevron with hover/focus/pressed treatment and a frosted sheet lip. Tiny monochrome card-top fragments reflect existing owned slots; an empty inventory shows only the sheet lip. The arrow is explicitly visual only and does not open a sheet or consume packs.
- The existing idle controller fades metadata, keycap, currency, arrow/peek, wordmark and dev panel while the pack keeps breathing. Keyboard focus and named visibility holds retain chrome. The Space hint uses existing tutorial/completed-opening state for the first-visit treatment without adding a tutorial visibility hold.
- Effects run through the shared scheduler, stop drawing while hidden, and do not run behind the finish gallery. Reduced motion removes float/lean, rolls, particles, slosh and chevron movement; arrival and currency shine use stationary fades. The timestamp fill remains continuous. At the full cap with reduced motion, the shared scheduler can sleep after transient fades settle. Pack motion does not force the stationary dot grid to redraw.
- Tab titles follow actual saved stock on arrival, consumption, reset and visibility changes. Visible tabs read `Cardable`; hidden tabs with stock read `Cardable · pack ready`. The existing delayed title-only dev event stays transient and leaves saved state and pack effects untouched.
- Dev controls cover empty, halfway, nearly ready and all three countdown formats; granting, consuming and skipping packs; currency changes; and reset. The near-ready preset arrives in about two seconds, subject to the existing one-second reconciliation tick. Dev consumption is a stock test only and does not resolve cards.
- Verification: 18 Stage 4 behavior groups pass in `node tools/check-stage4.cjs`. All 72 earlier-stage behavior groups and the six Stage 0 console checks pass. JavaScript syntax, diff whitespace and existing-config comparison checks pass. The instrumented runtime logs no application errors. Checks cover continuous fill, one-shot deduplication, load/visibility catch-up, clock rollback persistence, cap behavior, rolls/carries, vial slosh, currency persistence, idle/focus, reduced motion, gallery isolation and title integration.

3. Use **Waiting: empty** and **Waiting: halfway**. Inspect the fill, meniscus and specks. In the console, compare `Cardable.packView.progress` with `Cardable.timers.progress(Date.now())`; the small difference should only be time since the last rendered frame. 4. Use **Waiting: hours**, **Waiting: minutes** and **Waiting: seconds** to inspect all formats and digit rolls. Only changed digits should roll; literal units should remain steady. Check the currency carry transitions by using its dev control several times.
5. Use **Waiting: nearly ready**, **Grant a pack**, and **Skip timer**. Check one restrained bright sweep and lift per arrival, then stable opaque readiness. At two packs, the timer must pause and read `Stock full`; another grant must do nothing. Keep the pointer moving if you want to inspect vials while the idle fade would otherwise hide them.
6. Use **Add currency (dev only)**. Confirm a smooth count-up and subtle white shimmer. Reload to confirm the balance persists; use **Reset save** to return to the default stock/balance.
7. Leave the pointer still for 2.5 seconds. Only the pack should remain visible after the 600 ms fade; movement should restore chrome in 150 ms. 8. Toggle reduced motion during waiting, arrival and currency changes. Check stationary state/fade equivalents and continuous fill. Switch tabs through a ready event; confirm pause/catch-up, no expired sweep replay, and correct visible/hidden titles.
9. Open `?dev=1&gallery=1` and confirm all 28 finish previews remain intact with one full render. Capture ready-stack, waiting-halfway and arriving screenshots before visual acceptance.
