# Purchase history and persistence checks

2026-10-13 · isolated `feature/daily-shop`, following `7eb5cac`. No merge, release or deployment.

The header receipt icon opens Purchase history. It shows retained local transactions with actual paid Credits, saved timestamps, current ownership state, Cards/Packs filtering and eight-row pagination. Serial, finish and receipt ID expand on demand. Owned cards lead to their exact saved instance. Ready Titan packs use the existing opening handoff; reserved compact openings and kept results have separate states. Deleted or missing copies keep their receipt with no View action. Older kept Titan results without provenance are not guessed. The list creates no card views or timers and writes no gameplay state.

An inventory bridge bug meant an explicit Shop instance ID reached the correct stack but its detail still opened copy zero. The optional instance ID now reaches initial detail selection. Its full view is replaced only when another owned copy was requested. Missing explicit IDs do not silently open a substitute. Ordinary stack clicks keep their existing first-copy behavior, and the selected view returns through the normal inventory cleanup path.

`check-shop-history.cjs` passed 13 real purchases across three local-day fixtures, pagination, filters, non-spending browsing, exact non-first serial selection, missing ID, the ready/opening/owned Titan lifecycle through the existing compact commit/Keep API, no natural reward, deletion, export/import and repeated history return without subscriber growth. At 390×844, the mono list has no horizontal overflow and its rendered controls meet the 44 px target. The test closed Chrome, relaunched a new browser process with the same isolated profile, and compared encoded inventory identity, Credits, serial counter, Shop receipts/days and preferences. All matched; no page errors or HTTP requests occurred. Main charge/shroudDial/reveal acceptance remains the prior Stage 3 check.

The source backup hash was unchanged. Neither the backup contents nor diagnostic profile are committed. This checks compatibility with the existing collection; it does not reproduce the owner's reported failure or launch an installed Shop build.
