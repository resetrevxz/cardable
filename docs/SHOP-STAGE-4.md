## Final refinements

- The showroom keeps the real Titan pack and real catalog card art dominant. At 1024 px the exhibit is narrower so its metal base clears the stage plaque. Header Help and Close controls now have 44 px targets. The first open of a new rotation gives four offers a short, staggered turn; the hero enters once per presentation. Both effects use transform/opacity, stop when the sheet unmounts, and are absent in Very Low or saved reduced-motion mode. Neither delays interaction.
- The existing command palette includes **Open Shop**, in addition to the menu entry and inline Shop Help. The inherited modal shield traps keyboard focus and returns it to the entry on Escape/Close. The hold control remains the kit's 1.4-second confirmation for card and pack, with early release, cancel and failure leaving Credits untouched.
- Shop purchases use the same tolerant validation as a normally loaded historic save, so an unrelated retired GPU ID in inventory no longer blocks a valid purchase. The exact offered card is still checked against the current registry. Purchased Titan cards retain `source:'shop-pack'` plus an entitlement ID after Keep. Old pending Stage 3 reservations gain those fields on load; already kept old cards cannot be attributed without guessing.
- The bounded receipt history keeps the receipt of an active unopened Titan entitlement. A capped-history fixture bought a later daily card, retained exactly 64 receipts, and reloaded with the entitlement intact.
- The non-spending Stage 1 showroom smoke was updated to check current saved offers and interrupted holds. Stage 2/3 transaction checks remain intact, with a new Titan provenance assertion. `tools/check-shop-stage4.cjs` covers viewport geometry, 44 px targets, command palette, focus return, resize during hold, legacy-save purchase, reload and high-DPI overflow.

## Design reference application

Cardable [Designs.MD](../Designs.MD) remains the authority. [Apple design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles), [layout](https://developer.apple.com/design/human-interface-guidelines/layout), [materials](https://developer.apple.com/design/human-interface-guidelines/materials), [motion](https://developer.apple.com/design/human-interface-guidelines/motion), [feedback](https://developer.apple.com/design/human-interface-guidelines/feedback), and [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) informed the single-object hierarchy, restrained surface depth, brief motion and explicit success/failure copy. [Vercel's interface guidelines](https://vercel.com/design/guidelines) informed the focus return, 44 px controls, tabular Credits, semantic buttons, labelled states and transform/opacity animation. Apple's page bodies required JavaScript in the automated reader; the indexed official page text and Cardable's local rules were used. No visual claim depends on an inaccessible page detail.
