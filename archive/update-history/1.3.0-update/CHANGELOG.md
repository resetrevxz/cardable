# Cardable 1.3.0

- Rebuilt the developer menu as an optional premium workspace with ten registry-driven groups, fuzzy command palette, safe sandbox, snapshots, shared Settings controls and explicit Undo/held destructive actions.
- Added pack/time controls, forcing and shared odds/simulations, inventory/currency editing, finish lab, pure opening/tag playback, manual performance telemetry/recording/stress, event diagnostics, existing logic checks and frenzy/completion/showcase/photo/roulette tools.
- Preserved current single-finish rules. Combo, multi-finish and score features explain their unavailable data/runtime capabilities.
- Combined the current silver/glass visual refresh, full-art card presentation, roster/image generation, offline fonts, currency feedback and idle/AFK behavior into this release. Card roster manifests and shipped local artwork accompany the update.
- Archived the old menu/gallery/profiler and their historical command-line harnesses. Ordinary play loads no developer modules or CSS, and no logic checks execute automatically.
- Fixed stale legacy configuration references that interrupted opening transitions and prevented card detail, tutorial and Settings initialization. Restored the visible Settings entry and protected the shared frame scheduler from callback failures.
- Bounded static inventory materials, reused the lightweight renderer for collection/peek thumbnails, removed thumbnail filter/reflection cost, and moved shelf viewport measurement outside the per-card paint loop.

Validation is limited to static syntax/reference/loading-order/whitespace checks and one requested file:// sandbox browser smoke check. No new developer automated tests, screenshot jobs or profiling jobs are added or run. See DELIVERY.md for the measured smoke result.
