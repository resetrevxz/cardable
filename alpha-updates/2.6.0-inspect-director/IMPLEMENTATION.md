## Offline art

The initial non-file-writing probe used the installed Chrome 154.0.8037.97 and Edge 154.0.4258.53. Loading `apple-m1-gpu.webp` through file:// raised SecurityError for 2D readback, canvas export and WebGL texture upload. Supplying those same bytes as a data URI passed each operation. No game, screenshot or recording was involved in that constraint probe.

Run from the game root whenever original card artwork changes:

```powershell
node scripts/build-art-data.js
```

This creates 123 individual classic registration scripts plus an availability manifest under `assets/art-data/`. Thumbnails are excluded. The manifest is loaded only on first Inspect entry; artwork scripts are requested per selected card and removed after registration. `Cardable.art.register(id, dataUri)` is an additive overload installed by the studio; existing DOM generator registration and image rendering remain unchanged. Missing art-data registrations fall back to the game's procedural SVG art, rasterized as embedded vector data. A bounded three-entry URI cache is cleared on exit; pending image requests are cancelled.

## Foundation

- The existing detail-actions registry provides Inspect; E opens the selected serial. Unowned mystery cards do not expose it.
- The studio paints front/back, current artwork, real fonts, spec icons, serial, tier meter, compact tags and Standard/Classic skin identity. High/Medium/Low/Very Low texture widths are 2048/1536/1024/768. Classic uses the already-authorized VT323 terminal font. Static finish painting uses declared/computed palettes and exposed pure painters; animated finish ports remain E.
- A private WebGL2 renderer draws a thin rounded slab with beveled edges and a normal/roughness texture. Its fixed key light responds to the orbit camera. Very Low and unavailable WebGL use a simple 2D preview. No DOM card screenshot supplies a texture.
- Drag/arrows orbit, scroll or plus/minus dolly, F frames, and Card controls switch front/back or the plate. Backdrop brightness is adjustable. Esc deselects, then exits; Exit returns immediately through the transition. Space remains reserved for E's turntable.
- Last scene is keyed by the exact instance. Optional `save.studio` is normalized without changing the gameplay save schema. Existing saves without this field retain their defaults. Only Studio-owned scene data is written by the feature.
- Entry suspends refill polling and menu activity timers, pauses background CSS animations, hides/inerts background surfaces and acquires the shared scheduler's Studio-only scope. Exit restores focus/detail side, releases that scope, reconciles timestamp-based refills, and destroys studio GPU resources, canvases and observers. Static views sleep; no private animation loop runs.
- `studio:enter` and `studio:exit` emit `{cardId, instanceId, at}` once per successful lifecycle. `studio:photo` begins with actual captures in D.

No cutscene engine, cutscene finish, pack registry, opening style or packs.js content changes in the studio feature diff. The small shared changes are script/style registration, optional save normalization, app version, scheduler scope and menu-timer suspension.

## Milestone B — lights and camera

- Six light types: point, spot, directional/sun, rectangular area softbox, strip and ambient/sky with separate top/bottom colors. The card's normal/roughness material receives every active light's diffuse/specular contribution, including beveled edges. Spot cones support procedural blinds, grid, leaves and stars gobos. Area/strip integration uses four bounded samples.
- Light controls include name/type, position/rotation, intensity, HSV with an interactive neutral hue ring, pastel/neon/warm/cool presets, Kelvin temperature, size, falloff, cone softness, shadow toggle/softness and animation speed. Light rows support selection, visibility, locking and deletion; duplicate and delete also have the specified shortcuts. Counts are bounded by the live tier and warn near the limit.
- Viewport light gizmos move on the camera plane, move in depth, rotate and change size; Shift snaps transforms. Projected cone/rectangle/strip shapes track their spatial orientation. Arrow keys provide handle adjustments. Offstage lights retain clamped edge handles so they remain reachable.
- The studio owns analytic rounded-slab shadows on its floor/wall backdrop receivers. High uses bounded soft sampling; Medium basic shadows; Low/Very Low none. These receivers support B's card shadow; the editable floor/other shadow-casting geometry belongs to C's prop catalog.
- Camera tools include orbit, Shift/right-drag pan, dolly, FOV, roll, target controls, auto-frame, lock-to-card and aspect guides for 1:1, 4:5, 16:9, 9:16 and card-only. High adds a world-space focus picker, aperture-controlled depth gather and tilt-shift. Post includes exposure, quarter-resolution bloom, vignette, static grain, chromatic aberration and a procedural flare approximation. Medium retains bloom; lower tiers omit DOF/bloom. Simple mode offers distance, roll, framing and one static colored light.
- Fifty undo steps restore the full implemented scene; sliders/drags coalesce into gestures, keyboard actions and presets are atomic, redo clears on a new edit. Auto-frame affects the rendered scene without generating hidden history entries. Last scene preserves B data without a save schema bump.
- Eight light rigs: Studio, Rim, Noir, Neon Alley, Sunset, Moonlight, Showroom and Vault. Scene presets: Studio, Museum, Neon Alley, Sunset Desk, Void, Vault, Showroom and Surprise me. These establish B's camera/light/backdrop/post compositions; prop arrangements arrive in C.
- Pulse/flicker use continuous low-contrast ramps capped at 1.8 Hz Safe / 5 Hz Full by the current read-only cutscene profile. Sweep/orbit are slower spatial changes; ambient sky stays static. Reduced motion and Very Low pause animations. Animation uses presentation seconds from the shared scheduler, unaffected by developer timescale; hidden/unfocused pause does not advance its clock.
- Static scenes render only when dirty. Transforms reuse card textures and render targets; GPU allocation occurs only on entry, card-face changes or viewport resize. Bloom skips its passes at zero strength. No private RAF, animation timer, profiling or normal-game rendering is added. All B edits are confined to studio files and this report.

## Milestone C — props and scenes

- All 35 catalog entries are procedural: eight stage props, five fixtures, nine effects, seven hardware props and six decor props. Stage materials include matte/glossy/mirror floors, color/gradient backdrops, square/round plinths, an easel, glass case, turntable and grid floor. Fixtures include softbox/ring/neon/can/LED geometry; neon text is limited to twelve characters. Hardware includes spinning fan blades, heatsink fins, cables, PCIe bracket, RGB strip, screws and standoffs. Decor includes crown, trophy, laurel, plant, packs and collection cards.
- Every active light contributes to prop diffuse/specular shading. The key light adds a cached depth shadow pass on High (1024, soft sampling) and Medium (512, basic); Low omits it. Card and eligible prop transforms invalidate the depth pass; camera-only edits do not. Mirror floors use one half-resolution reflected scene pass. Glass uses a safe color-buffer copy and screen-space refraction approximation. Haze/smoke use layered lit billboards; the other effects use bounded procedural sprite batches. These are deliberate approximations, not imported models or images.
- Meshes are pooled by catalog type inside the renderer. Effect batches share a scene-wide budget of 512/192/48 particles on High/Medium/Low, further reduced by density and each mesh's own cap. Only needed mirror/glass passes allocate storage. The prop/face owner decodes sequentially, retains at most ten 256-by-358 collection faces and releases pending work and resources on exit. There is no private animation loop. Reduced motion freezes particles, spinning parts and spin/float animations; static flare props and Simple mode sleep.
- Props have color/material, position/rotation/nonuniform scale, cast-shadow, animation/speed, snap-to-floor, lock and visibility controls. The catalog warns near the 40/25/12/0 tier budgets. Eye/lock/delete and selection cover card, lights and props; an Objects panel provides the same rows when the side outliner is hidden. Shared viewport handles edit camera-plane/depth position, rotation and scale with Shift snapping and keyboard arrows. Clicking geometry selects its bounding volume. Duplicate/Delete and 50-step history extend to props.
- Up to ten collection cards across the whole scene, arranged as stacks, fans or walls. Only owned instance IDs are retained on import. They use the existing face painter at a lite texture size; unported finishes/variants retain the same preview limitations as the primary card.
- Pack props read the existing pack/skin registries without editing them. The Classic skin's existing procedural canvas painter is used directly. Other skins use their declared material palettes and original procedural wrapper geometry/marks with studio-owned adapters. Brand packs use their company names rather than loading file image logos, keeping props procedural and origin-clean. Royal/Titan adapters approximate their wrapper composition; they do not run opening/cutscene effects.
- Scene JSON version 1 now preserves/sanitizes prop transforms and settings, hidden/locked state and unique object IDs. Optional save normalization retains ten named slots and bounded embedded thumbnails as well as Last scene. Each slot saves a 160-by-100 render thumbnail; these are product scene thumbnails, with no QA screenshot files created. Save/load/delete and copyable JSON import/export live in the Scenes panel. Import is bounded to 256 KiB and keeps the exact entered card identity. Clipboard failures leave selected JSON ready for the normal copy shortcut.
- All eight scene presets now include tier-bounded prop arrangements. Presets and imported/loaded scenes remain atomic undo operations. Space stays reserved for E's director turntable; C's turntable prop spins through the studio clock.
- Ordinary design assumptions: deleting the primary subject hides it while preserving its collectible identity, with Undo/Show restoring it; loading a scene changes its composition around the entered instance. These actions never remove inventory cards. Brand image logos fall back to declared textual identity. Glass, fog, shadows and pack materials use the approximations described above.
- All C changes are limited to src/studio and this report. Gameplay save version remains 5. Shared cutscene, pack registry/data and opening files are unchanged.

## Milestone D — photos and album

- The Photo panel supports 1080p, 2K, 4K and custom whole-pixel sizes, PNG/JPEG/WebP, compression quality, caption/name, no frame/Polaroid/museum label/collector slab, and a small optional Cardable watermark that starts off. Photo guides preview the content crop, including the frame's inset. Finished dimensions include the frame. Presets are 1920 × 1080, 2560 × 1440 and 3840 × 2160 before matching the chosen aspect guide; custom output is constrained by both GPU hardware limits and a 32-megapixel CPU memory cap. Simple mode caps the longest edge at 1920 and total pixels at 1920 × 1080, including portrait crops.
- A capture snapshots the scene and presentation time, freezes live animation/editing, paints its own origin-clean face, waits for its own bounded collection-face owner, and uses a temporary renderer. Highest quality is offered regardless of the live WebGL tier; Simple remains Simple. The live renderer/tier is retained. Export tiles have at most a 1536-pixel edge, overlap for lens/refraction/bloom kernels, and use a cropped projection with global gradient/grain/flare/lens coordinates. Pixels are read immediately after each draw, vertically corrected and stitched into a 2D output. CPU output is bounded; all job targets, textures, meshes, faces and canvases are released in finally. There is no private RAF or persistent capture timer.
- Exit, save replacement, detail reset, visibility pause and Esc during capture cancel the job. No cancelled capture adds a photo or photo event. A completed capture emits the specified studio:photo payload once, including actual output dimensions and a unique photo ID. Studio entry/exit contracts remain intact.
- The shutter uses the shared studio clock for a viewfinder snap, thin sweep and soft vignette dip; the product thumbnail moves toward the album. It never flashes the full screen white. Reduced motion removes movement/sweep. Photo controls lock during capture while Exit remains available. Static views sleep after the short effect.
- IndexedDB owns photos outside the gameplay save: id, cardId, instanceId, createdAt, width/height, full Blob, thumbnail Blob, scene JSON and name. An atomic write transaction enforces the 100-photo limit. The album does not evict existing photos. Connections open for explicit operations and close after their users finish; blocked/failed opening requests close their eventual connections. Storage exceptions leave the latest photo available and automatically offer a download with a notice; they do not silently create an in-memory persistent album.
- A bounded studio filmstrip shows the latest twelve thumbnails. The album sheet shows a grid with lazy thumbnail images, loads only the selected full photo, and supports download, rename, delete, image clipboard and reopening its saved scene. Count/photo-byte usage and browser usage/quota from navigator.storage.estimate update on capture, rename, delete and opening the sheet. Object URLs are revoked on replacement/close. The album temporarily acquires its own scheduler scope, focus trap and menu/refill suspension; closing restores the prior studio or normal view.
- The existing inventoryTabs registry supplies the inventory Photo album entry; the existing context-menu registry supplies the background menu entry. No new toolbar registry was necessary. The shared context-menu guard adds Studio/Album surfaces. A small additive detail.selectInstance callback selects the exact saved serial, waiting for a current serial crossfade when necessary. Reopening an unowned/deleted serial is disabled, while its photo remains downloadable. Reopening a different owned card uses existing detail/inventory events rather than polling.
- Scene JSON version 1 accepts an optional presentationTime for frozen animation phase; gameplay save schema stays 5. No pack registry, pack data, opening styles, cutscene engine/helper or cutscene finish files were edited. The C prop mesh branch defect for pack/collection was repaired, and export asset owners now expose an explicit ready promise.
- Assumptions: 2K denotes 2560 × 1440; requested pixels describe the finished framed file; hardware limits also constrain final custom dimensions, with an additional 32-MP memory cap. Clipboard uses PNG for compatibility, converting JPEG/WebP only when requested, and reports permission/API failures as a download alternative. Frames and pack/glass/finish approximations remain procedural. A separate small IndexedDB checks store isolates the explicit blob check from the user's 100 photo slots.

D testing: one Chrome file:// game session exercised final tiled 4K PNG capture/download, custom WebP slab and JPEG museum frames, image clipboard, rename/delete/usage, inventory and context entries, exact-serial scene reopening, Simple portrait capture, unavailable-storage download, cancellation and exit cleanup with zero console/WebGL errors; checkStudio ran exactly once and passed all seven cases in 16 ms; no old tests, new test files, QA screenshots, recordings or profiling.

D acceptance covers that desktop Chrome session and product photo decoding at the requested dimensions. Updated studio modules and the exact-serial/check functions were applied in the existing session instead of reloading the game. A final source-only cleanup refinement makes the detail pointer callback retain the restored card view rather than the entire ended studio session. Cross-browser clipboard/storage behavior, physical-device performance and visual fidelity across all skins/finishes are not certified.
